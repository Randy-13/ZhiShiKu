# Mature Web Architecture: 知识酷

## 设计判断

知识酷的功能树已经很清楚，但成熟网页不能把功能树原样铺到页面上。功能树回答的是“系统能做什么”，网页架构回答的是“用户此刻该在哪里完成什么任务”。

知识酷应该采用稳定的应用外壳：

```text
左侧边栏：稳定导航和对象入口
顶部栏：当前空间、全局搜索、快捷创建、状态和设置
中间工作区：当前任务的主操作区
右侧上下文栏：选中对象详情、结果、建议、检查清单
底部/抽屉：长任务进度、运行日志、错误和后台队列
```

这种结构比当前“多个大面板同屏堆放”更适合你的产品，因为你的功能分为材料、知识、挖掘、创作、配置几类，而不是同一个页面上的并列按钮。

## 顶层信息架构

成熟版知识酷建议有 5 个一级区域：

```text
收集
学习
挖掘
创作
设置
```

它们对应你图里的主干：

- 收集材料 -> 收集
- 学习知识 -> 学习
- 挖掘 -> 挖掘
- 运用知识 -> 创作
- 其他网页基础功能 -> 设置

不要把“文本框键入、截图、文档、音视频、链接”做成一级导航。它们是收集区的输入方式。

不要把“作家、投资人、学生、创业者、研究员”等做成一级页面。它们是挖掘区里的视角模板或分析角色。

不要把“生成文章、配图、美编、发布检查”做成散落按钮。它们应该是创作区的线性步骤。

## App Shell 布局

### 左侧边栏

左侧边栏只放稳定区域，不放一次性动作。

推荐结构：

```text
知识酷

收集
学习
挖掘
创作

资料库
知识库
策略库
作品库

设置
```

说明：

- 上半部分是工作模式。
- 下半部分是核心对象库。
- 设置固定在底部。
- 当前页面不要再用多个同级 tab 承担产品导航。

### 顶部栏

顶部栏负责全局动作：

```text
当前工作区标题
全局搜索
新建/导入
任务队列状态
API/模型状态
用户/设置入口
```

全局搜索应能搜：

- 原始材料
- 知识文件
- 图谱节点
- 策略文件
- 文章工作区

### 中间工作区

中间工作区只做当前页面最重要的一件事。

例如：

- 收集页：导入材料、预处理、合并为项目。
- 学习页：提炼知识、分段规划、生成知识文件和知识网。
- 挖掘页：选择视角、运行信息挖掘、产出信息文件。
- 创作页：选择知识材料，按步骤生成文字/图文/视频内容。

### 右侧上下文栏

右侧栏不做主导航，只显示当前选中对象的上下文：

- 当前材料详情
- 解析结果
- 知识预览
- 图谱节点详情
- 挖掘视角说明
- 写作发布检查清单
- 模型调用日志和错误详情

### 底部任务抽屉

长任务不要占据主页面。

以下任务适合进入任务抽屉：

- OCR
- 文档解析
- 音视频转写
- 长文档分段规划
- LLM 提炼
- 图谱重建
- 图片生成
- 发布预检

## 功能放置规则

### 收集

收集区解决“材料怎么进来，以及进入后是否可处理”。

应该放：

- 文本框键入
- 截图
- 文档
- 音视频
- 链接
- 材料格式解析
- 材料类型识别
- 多材料入列整合
- 材料处理预规划

不应该放：

- 知识图谱浏览
- 写文章
- 发布公众号
- 多视角挖掘

成熟交互：

```text
导入材料 -> 自动识别类型 -> 显示材料卡片 -> 可合并为项目 -> 进入学习
```

### 学习

学习区解决“材料如何变成可复用知识”。

应该放：

- 提炼重点
- 将庞杂文字梳理成核心知识簇
- 生成知识文件
- 构建知识网
- 入网确认

学习区是知识酷的核心。它应该比图谱浏览和写作更靠前。

成熟交互：

```text
选择材料/项目 -> 预览分段 -> 设置提炼目标 -> 生成知识文件 -> 审阅 -> 入网
```

### 挖掘

挖掘区解决“从不同人的视角重新解读知识的信息量”。

你图里列出的视角很重要，但它们不是页面结构，而是挖掘模板：

- 作家：文字组织逻辑、节奏、表达方式。
- 投资人：散户、游资、机构、主力、市场信号。
- 学生：与工作就业的相关度。
- 创业者：行业需求和机会。
- 行业研究员：行业底层分析。

成熟交互：

```text
选择知识/材料 -> 选择视角模板 -> 配置挖掘问题 -> 运行挖掘 -> 产出信息文件 -> 保存为策略/报告
```

挖掘区的产物不是普通知识文件，而是“信息文件”或“视角分析文件”。它们可以反哺学习区和创作区。

### 创作

创作区解决“如何运用知识形成可发布内容”。

文字创作是当前优先级最高的创作类型，应该按线性流程组织：

```text
1. 选择知识材料
2. 生成选题
3. 生成文章
4. 修改文章
5. 配图
6. 美编
7. 发布前检查
8. 发布公众号草稿
```

小红书图文和视频创作可以先作为待实现入口，不要和文字创作抢主流程。

成熟交互：

- 左侧：当前作品流程步骤。
- 中间：当前步骤编辑器。
- 右侧：材料引用、检查清单、预览和日志。

### 设置

设置区解决系统基础能力。

应该放：

- 用户信息
- LLM 配置
- ASR 配置
- 图片生成配置
- 本地依赖检测
- 标准配置
- 模板管理

设置不应分散在多个页面弹窗里。短期可以保留弹窗，长期应收敛到设置中心。

## 推荐路由

短期可以不立刻改路由，但长期目标应是：

```text
/collect     收集材料
/learn       学习知识
/mine        挖掘信息
/create      创作内容
/library     对象库
/settings    系统设置
```

其中对象库可继续细分：

```text
/library/materials
/library/knowledge
/library/network
/library/strategies
/library/works
```

如果想更贴近桌面工具，也可以使用一个 `/app` 主入口，在内部用侧边栏切换工作区。

## 当前页面应如何重排

### 当前首页

当前首页应该拆成：

- 收集区：截图、文档、音视频、链接输入。
- 学习区：队列、规划、知识生成、入网。
- 知识库：知识列表、筛选、预览。
- 知识网络：图谱和问答。

不建议继续把策略学习、图谱、检索和材料输入全部压在首页。

### 当前媒体页

媒体页不应该是孤立工具页。它应该被并入“收集”：

- 链接解析是收集输入方式。
- 音视频转写是材料预处理。
- 字幕文件是材料附件。
- 从媒体生成知识属于学习区。

### 当前写作页

写作页方向正确，但需要从 tab 变成创作流水线。

保留的顺序：

```text
材料 -> 选题 -> 文章 -> 修订 -> 配图 -> 美编 -> 发布检查 -> 发布
```

“运行日志”不应是主 tab，应该进入右侧上下文栏或底部任务抽屉。

### 当前策略学习

策略学习应该独立为“挖掘”或“策略学习”区。

它的核心不是上传不同材料，而是：

- 选择样本
- 选择分析视角
- 学习结构和表达策略
- 保存策略版本
- 应用到创作

## 优先整理的交互环节

第一优先级：

- 把“收集材料”和“学习知识”拆成两个连续阶段。
- 把多种输入方式统一为材料卡片。
- 把“分段规划”变成学习前的明确审阅步骤。
- 把知识文件、知识网、信息文件、作品文件区分清楚。

第二优先级：

- 把图谱和问答从首页中拆成知识网络。
- 把策略学习从首页中拆成挖掘区。
- 把媒体页并入收集/预处理流程。

第三优先级：

- 建立统一设置中心。
- 把日志和长任务进度做成任务抽屉。
- 再考虑是否迁移 React/Vite。

## 设计原则

- 功能树不是导航树。
- 输入方式不是一级页面。
- 长任务必须有进度和可恢复状态。
- 配置不和主任务争夺工作区。
- 创作流程必须线性，不能让用户在多个并列 tab 里猜下一步。
- 挖掘视角是模板，不是页面。
- 知识文件、信息文件、策略文件、作品文件必须在产品语言上区分。
