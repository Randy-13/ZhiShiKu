# Product Interaction Architecture: FigureLearning

## 重新定义产品目标

FigureLearning 不应该只是“截图转知识”的页面集合，而应该被定义为一个个人研究与创作工作台：

```text
收集材料 -> 提炼知识 -> 组织知识 -> 检索理解 -> 形成观点 -> 生成内容 -> 发布复盘
```

所以网页交互的核心不是展示所有功能，而是让用户始终知道：

- 我现在处在哪个工作阶段。
- 我手里的材料是否已经变成可复用知识。
- 哪些知识已经入网、可检索、可写作。
- 下一步最自然的动作是什么。

## 功能优先级

### P0: 主工作流，必须最清晰

1. 输入材料
   - 截图
   - 文档
   - 音视频或字幕
   - 外部链接

2. 生成知识
   - 本轮材料队列
   - 解析进度
   - 分段规划
   - 生成结构化 Markdown 知识

3. 知识库管理
   - 查看知识文件
   - 搜索和筛选
   - 预览 Markdown
   - 删除未入网知识

4. 入网与检索
   - 将知识纳入图谱
   - 处理待确认节点
   - 基于本地知识回答问题

### P1: 创作工作流，应该从知识库自然进入

1. 选择知识材料
2. 生成选题
3. 生成文章
4. 修订文章
5. 配图
6. 美编
7. 发布前检查
8. 发布公众号草稿

### P2: 策略学习工作流，属于高级能力

1. 创建挖掘项目
2. 添加样本文档、截图、媒体、链接
3. 学习创作策略
4. 版本化策略沉淀
5. 在写作工作流中复用策略

### P3: 系统配置，应该降低视觉优先级

1. LLM API 设置
2. ASR 设置
3. 图片 API 设置
4. 本地依赖检测
5. 连接测试和运行日志

配置是必要能力，但不应该和主工作流争夺页面中心位置。

## 推荐页面层级

### 一级导航

推荐将产品分成四个一级区域：

```text
知识工作台
知识网络
写作工坊
策略学习
```

系统设置作为右上角全局入口，不作为一级工作区。

### 知识工作台

这是默认首页，承载 P0 主链路。

页面结构建议：

```text
顶部：当前工作区 + 全局动作

左侧：材料输入
  - 截图
  - 文档
  - 音视频/链接

中间：本轮工作
  - 队列
  - 解析方式
  - 分段规划
  - 生成按钮
  - 进度和错误

右侧：知识结果
  - 最近生成
  - 搜索筛选
  - 入网状态
  - 写作入口
```

交互原则：

- “生成知识”是本页最强主按钮。
- “分段规划”是长文档/长媒体的中间步骤，不应和最终生成动作同级混杂。
- 队列、规划、结果应该是一条从左到右或从上到下的连续流程。

### 知识网络

这是理解和检索空间，不应和材料输入混在同一个主区域里。

主要能力：

- 图谱浏览
- 待确认节点
- 节点合并/重命名/删除
- 本地知识问答

交互原则：

- 图谱操作是组织知识，不是生成知识。
- “重建图谱”属于危险/维护动作，视觉优先级应低于浏览和确认。
- 检索问答应明确引用来源知识文件。

### 写作工坊

这是从知识库进入的 P1 流程。

推荐步骤：

```text
材料确认 -> 选题 -> 初稿 -> 修订 -> 配图 -> 美编 -> 发布检查 -> 发布
```

交互原则：

- 使用 stepper 或明确工作阶段替代过多并列 tab。
- 每一步只暴露当前阶段最关键动作。
- 发布必须显示 checklist，不应让用户在缺封面、缺 HTML 或未预检时误点。

### 策略学习

这是高级能力，不应放在默认首页主链路里和“生成知识”抢注意力。

推荐结构：

```text
项目列表 -> 样本素材 -> 学习策略 -> 策略版本 -> 应用到写作
```

交互原则：

- “策略学习”是为写作工坊服务的能力。
- 策略产物应该能被写作流程引用，而不只是孤立展示。

## 当前页面的主要问题

- 首页同时承担材料输入、知识库、图谱、检索、策略学习和设置，认知负荷过高。
- “精炼知识”和“挖掘创作策略”作为同级 tab，但它们不是同一层级的用户任务。
- 媒体能力既出现在首页输入 tab，又有独立 `/media` 页面，入口关系不够清晰。
- 图谱和知识生成并排出现，导致“生成”和“组织/检索”边界模糊。
- 写作页已经接近完整工作流，但 tab 过多，阶段关系应该更像流水线。
- 设置弹窗能力完整，但在主页面视觉上过重，应统一为全局设置中心。

## 目标交互架构

长期建议形成以下信息架构：

```text
/
  知识工作台
  - 输入材料
  - 生成知识
  - 最近知识

/graph
  知识网络
  - 图谱浏览
  - 待确认节点
  - 本地问答

/writer
  写作工坊
  - 材料确认
  - 选题
  - 文章
  - 配图
  - 美编
  - 发布

/mining
  策略学习
  - 项目
  - 样本
  - 策略版本

/settings
  系统设置
  - LLM
  - ASR
  - 图片生成
  - 环境检测
```

第一阶段不需要立刻改页面路由，但后续代码拆分应按这个目标层级推进。

## 对代码架构的影响

代码不应只按旧页面拆，而应按产品能力拆：

- `workbench`：材料输入、队列、规划、知识生成。
- `library`：知识列表、搜索、状态、预览。
- `network`：图谱、待确认节点、本地问答。
- `writer`：文章生产流水线。
- `mining`：策略学习项目。
- `settings`：全局配置中心。

后端领域模块和前端页面不必一一对应。后端继续保持更细的能力边界：

- `uploads`
- `documents`
- `media`
- `knowledge`
- `graph`
- `writer`
- `mining`
- `settings`
- `llm`
- `ocr`

前端则应该按用户心智组织：

- `workbench`
- `network`
- `writer`
- `mining`
- `settings`

## 近期实施顺序

1. 先保留现有页面，不做大 UI 改版。
2. 在架构层建立产品能力登记表，避免后续只按旧文件迁移。
3. 后端继续机械化拆 `settings` 与 `uploads`，但命名和文档要对应产品层级。
4. 等后端能力稳定后，再重排前端入口：
   - 首页收敛为知识工作台。
   - 图谱/检索独立为知识网络。
   - 策略学习从首页剥离。
   - 设置统一为全局设置中心。
