# 知识酷使用文档

## 快速开始

知识酷把一次知识工作流拆成七个主要工作区：收集、学习、挖掘、创作、小红书、知识库和设置。最稳的顺序是先把外部素材保存成原文，再从原文生成重点知识，最后按视角解读、进入公众号创作或制作小红书图文笔记。

- 收集：把文本、图片、文件、音视频或链接整理成可编辑原文。
- 学习：从原文库勾选来源，生成重点知识草稿并确认入库。
- 挖掘：选择原文和视角，用 RTFC 结构生成视角解读。
- 创作：引用三库内容推进选题、初稿、修订、配图、美编和发布检查。
- 小红书：围绕账号定位生成图文/轮播笔记，并分步填入发布页。
- 知识库：编辑原文库、重点库和视角库中的 Markdown 文件。
- 设置：检查 API、OCR、ASR、图片配置、B 站 Cookie、小红书登录和本地存储。

[进入收集](#/collect) [查看设置](#/settings)

## 素材收集

收集区只做一件事：把外部素材整理成可保存的原文。你可以从文本、截图/图片、文档、音视频和链接入口加入素材，所有入口都会进入同一个素材队列。

### 推荐流程

- 先选择素材类型，再输入文本、上传文件或粘贴链接。
- 检查队列里的标题、来源、状态和错误提示。
- 点击生成原文，确认标题、备注和正文 Markdown。
- 保存到原文库。保存后不会自动提炼知识，也不会自动进入创作。

### 链接素材

普通网页链接会尝试真实提取网页内容。视频平台、B 站、抖音、小红书等链接需要走媒体或平台解析能力，不能只当普通文本保存。

[进入收集](#/collect)

## 知识学习

学习区用于把原文转成可复用的重点知识。来源必须来自右侧知识列表中的原文库文件。

### 推荐流程

- 在右侧知识列表切换到原文库。
- 勾选一个或多个原文文件。
- 加入学习队列，再点击生成重点知识。
- 检查草稿的标题、备注和正文，确认后加入重点库。

生成内容需要人工确认。不要把明显缺来源、缺上下文或格式异常的草稿直接入库。

[进入学习](#/learn)

## 视角挖掘

挖掘区用于把原文按不同视角解读为可保存的视角库文件。主区域是两栏：左侧管理视角，右侧运行视角解读。

### 视角字段

- 视角名：谁在阅读。
- 定位：这个视角关注什么类型的信息。
- 核心目标：这次解读要完成什么判断。
- 立场：默认的评估标准和判断偏好。

### 输出结构

视角解读遵循 RTFC，并输出五段式：立场与标准、原文信息提炼、专属分析、风险疑问、结论建议。确认后保存到视角库。

## 内容创作

创作区把知识确认、选题、初稿、修订、配图、美编、发布检查和发布串成一个项目流。创作项目优先引用已保存的知识文件，而不是临时复制片段。

### 推荐流程

- 从右侧知识库选择原文、重点或视角文件。
- 新建或选择创作项目。
- 生成选题，选择一个方向后生成初稿。
- 修订正文，再处理配图、美编和发布检查。
- 发布前检查摘要、图片、HTML 和平台限制。

图片生成如果部分失败，已成功的图片应保留；发布检查如果发现摘要过长，会优先自动截断到平台限制内。

## 小红书图文

小红书是独立工作区，只处理图文/轮播笔记。推荐路径是素材选择、账号画像、内容策划、选题、标题正文、封面图、轮播图、标签、发布预检、填入发布页、用户确认发布或保存草稿。

### 推荐流程

- 从知识库选择已保存文件作为项目素材。
- 先确认账号定位、目标人群、内容支柱、用户痛点和参考风格，再生成选题。
- 选择选题和内容形式。教程、清单、避坑、对比、案例类内容通常适合 3-7 张轮播图。
- 发布前检查标题、正文、封面提示词、slide plan、图片顺序和标签。
- 发布链路分步执行：登录检查、必要时二维码登录、填入发布页、浏览器中确认、发布或保存草稿。

### 发布预检

无图片、标题超长、正文为空、未登录或图片路径不存在时，发布预检应阻止继续。封面图固定为第一张，正文轮播图随后。

## 知识库管理

知识库分为原文库、重点库、视角库。中间主区域是文件编辑区，可以修改标题、备注和正文 Markdown。

### 保存规则

- 如果列表里只有元数据，选中文件后会自动读取 Markdown 全文。
- 保存会真实写回后端和 Markdown 文件。
- 原文库保存原始可读材料；重点库保存提炼后的知识；视角库保存按视角生成的解读。

不要直接删除运行目录中的知识文件。需要删除时使用界面或后端提供的删除能力。

## 设置与依赖

设置页集中管理语言、OCR/API 提取方式、API 配置、本地存储和全局运行日志。依赖检查至少包括 B 站 Cookie 状态和小红书登录状态。

### B 站 Cookie

B 站字幕提取优先使用 `FIGURELEARNING_YTDLP_COOKIES_FILE` 指定的 Netscape Cookie 文件。默认文件是 `auth/bilibili.cookies.txt`，该目录不会提交到 Git。

设置页会检查 Cookie 文件是否存在、格式是否可读，以及是否包含 `SESSDATA`、`DedeUserID`、`bili_jct`。真正能否下载字幕，要在收集区执行提取时验证。

[进入设置](#/settings)

## 版本管理与本地数据

大改开始前先检查当前分支、未提交改动和 `origin` 远端。如果工作区已经有未提交改动，不要在没有确认的情况下把不相关改动混进同一个提交。

不要提交 Cookie、本地数据库、运行媒体、截图产物、生成输出、`.env` 密钥或 `auth/` 内容。`knowledge/`、`images/`、`documents/`、`media/`、`writer/`、`raw_materials/`、`knowledge.db` 等用户数据应留在本地并单独备份。

准备推送版本前，按改动范围运行后端语法检查、相关后端测试、媒体解析测试、前端构建和编码检查。

## 故障排查

### 按钮不可用

禁用按钮通常会就近显示原因。常见原因包括没有选中来源、当前库类型不对、文件缺少 Markdown 路径、API 配置不可用或后台任务正在运行。

### 生成失败

先看素材队列或全局运行日志中的错误信息。再检查 API 设置、网络、B 站 Cookie、上传文件是否存在，以及对应 Markdown 文件是否能读写。

### 页面状态不一致

刷新页面后重新选择工作区和知识文件。如果问题仍然存在，先不要手动改数据库或运行目录，优先通过界面重新生成或保存。
